# خدمني Khidmini — مشروع تطبيق ويب حقيقي قابل للربط بقاعدة بيانات

هذه الحزمة مشروع React + TypeScript + Vite، وفيه واجهة عربية متجاوبة، وتسجيل حسابات عبر Supabase، وقاعدة بيانات SQL وسياسات صلاحيات. **لا يزال يحتاج إعداد مشروع Supabase ونشره قبل أن يعمل كموقع عام.**

## ما الذي يتوفر؟
- واجهة رئيسية عربية RTL متجاوبة مع الهاتف والكمبيوتر.
- بحث وتصنيفات وتصفية حسب المدينة.
- تسجيل وإنشاء حساب عبر Supabase Auth.
- ثلاثة أدوار في التصميم: عميل، مقدم خدمة، مدير.
- إضافة خدمات من حساب مقدم الخدمة بعد الموافقة عليه.
- إرسال طلبات حقيقية لقاعدة البيانات للحسابات المسجلة.
- عرض طلبات العميل ومقدم الخدمة وتحديث حالة الطلب.
- SQL لإنشاء الجداول والفهارس وسياسات Row Level Security.
- واجهة تجريبية واضحة عند عدم إعداد Supabase.

## ما الذي لا يعتبر جاهزًا تجاريًا بعد؟
- لا يوجد مشروع Supabase منشأ باسمك أو مفاتيح ربط حقيقية داخل هذه الحزمة.
- لا يوجد عنوان موقع منشور.
- لم يتم دمج بوابة دفع يمنية؛ لا تسجل أي مدفوعات على أنها ناجحة.
- واجهة التقييمات والجداول موجودة في قاعدة البيانات، لكن يلزم استكمال شاشة التقييم الفعلية.
- يلزم اختبار أمني ومراجعة السياسات قبل إطلاق عام. سياسة تحديث الطلبات في النسخة الأولية تسمح للمستخدم المرتبط بالطلب بتحديث الصف؛ قبل الإطلاق التجاري يجب تقييد انتقالات الحالة بحيث لا يستطيع العميل تغيير حالة التنفيذ بنفسه، ويفضل تنفيذها بدوال SQL موثوقة.
- إضافة حساب مدير وموافقة مقدمي الخدمات تتطلب عملية موثوقة من لوحة SQL أو لوحة إدارة خلفية، وليست زرًا عامًا داخل التطبيق.

## خطوات الإعداد من الهاتف
يمكن تنفيذ كثير من الخطوات من متصفح الهاتف، لكن إدارة مشروع برمجي كامل أسهل على الكمبيوتر. إذا لم يتوفر كمبيوتر، استخدم بيئة تطوير سحابية في المتصفح تدعم Node.js وGit.

### 1. إنشاء مشروع Supabase
1. افتح https://supabase.com من المتصفح وأنشئ حسابًا ومشروعًا جديدًا.
2. احتفظ بكلمة مرور قاعدة البيانات في مكان آمن ولا ترسلها لأحد.
3. افتح SQL Editor في لوحة Supabase.
4. انسخ محتوى `supabase/schema.sql` كاملًا وشغّله على مشروع جديد.
5. من إعدادات API انسخ Project URL وPublishable/anon key المخصص للواجهة الأمامية.

### 2. ربط التطبيق
1. انسخ `.env.example` إلى ملف باسم `.env`.
2. ضع القيم الحقيقية:
   `VITE_SUPABASE_URL=https://...supabase.co`
   `VITE_SUPABASE_ANON_KEY=...`
3. لا تضع service_role key في ملف الواجهة أو في أي مستودع عام.
4. ثبّت الاعتماديات باستخدام `npm install`.
5. شغّل `npm run dev` للتجربة أو `npm run build` لفحص البناء.

### 3. صلاحيات الحسابات
- كل تسجيل جديد يبدأ كعميل، حتى لو اختار المستخدم مقدم خدمة في نموذج الواجهة؛ هذا مقصود للحماية.
- لتفعيل مقدم خدمة بعد التحقق منه، افتح SQL Editor ونفّذ:
  `update public.profiles set role = 'provider', provider_approved = true where id = 'UUID';`
- لإنشاء مدير، أنشئ الحساب أولًا، ثم غيّر دوره من SQL Editor:
  `update public.profiles set role = 'admin' where id = 'UUID';`
- استبدل UUID بمعرّف المستخدم الحقيقي. لا تجعل هذا الإجراء متاحًا للمستخدمين في التطبيق.

### 4. النشر
ارفع ملفات المشروع إلى GitHub ثم اربطه باستضافة تدعم Vite مثل Vercel أو Netlify. أضف متغيري البيئة في إعدادات الاستضافة. أضف رابط النشر إلى قائمة Redirect URLs في Supabase Auth، واضبط تأكيد البريد الإلكتروني وسياسة كلمات المرور. لا تضع ملف `.env` في GitHub.

## تشغيل المشروع
```bash
npm install
cp .env.example .env
npm run dev
```
على Windows يمكن نسخ الملف يدويًا بدل استخدام `cp`. في بيئات الهاتف، استخدم محررًا سحابيًا يدعم Node.js.

## معلومات أمنية مهمة
- لا تنشر مفاتيح الخدمة السرية.
- سياسات RLS ضرورية، ولا تتجاوزها بمفاتيح service role في الواجهة.
- راجع إعدادات البريد الإلكتروني واستعادة كلمة المرور.
- اختبر حساب عميل ومقدم خدمة ومديرًا على حدة.
- اختبر محاولات الوصول إلى طلبات مستخدم آخر.
- أضف سياسة خصوصية وشروط استخدام ومعلومات تواصل حقيقية قبل الإطلاق.
- تحقق من قوانين الدفع والضرائب وحماية المستهلك المعمول بها محليًا.
